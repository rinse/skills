# software-engineering

## 目的

AI エージェントが、変更を何度重ねても仕様と構造を把握し続けられる開発を実現する。

## 概要

AI エージェントは変更を頼まれると、旧状態の否定、互換のための二重経路、旧概念を指す名前、変更の経緯を成果物に残す。
変更を重ねるほど成果物に履歴が積もり、仕様と構造が読み取れなくなって次の変更の質が落ちる。

対策は、日々の変更と、たまの掃除の二段に分け、スキルを一つずつ当てる。

- **日々の変更**は普通の差分で行い、残滓はスキル `clean-rewrite` で取り除く。文章の残滓に加えて、互換の二重経路や旧概念を指す名前といったコードの残滓も見る。
- **たまの掃除**は、残滓を取り除いても構造が旧版に引きずられているファイルに対して行う。スキル `redraw` が、旧版を見ない書き手にそのファイルを事実とテストだけから描き直させ、検査役が旧版と照合して落ちた振る舞いを報告する。

## 不変条件

- **成果物は自分の旧版と自分を生んだ会話を知らない。** 何をなぜ変えたかは返信とコミットメッセージに置く。
- **描き直しの入力は事実とテストだけである。** 旧版を読んでよいのは検査役だけで、書き手は読まない。
