# 全単位に共通する事実

## 不変条件

このプラグインは次の三つを保ちます。

- **仕様書が唯一の事実集合である。**
  プロジェクトの仕様は仕様書にだけ書かれ、変更はまず仕様書に入る。
  成果物は仕様書だけから描かれ、コード、ドキュメント、会話、種は仕様の出典にならない。
- **仕様書と成果物は歴史的経緯を含まない。**
  含んでよいのは執筆時点で真である内容だけである。
  履歴を書くこと自体が目的の文書（CHANGELOG、ADR、移行ガイド）は例外である。
- **仕様書と成果物は事実の水準で一対一である。**
  仕様書にある事実はいずれかの単位が実現し、単位のどの要素もいずれかの事実で正当化される。

変更の物語は仕様書にも成果物にも入らず、オーケストレーターの文脈にだけあります。
過去は Git の履歴にだけあります。

## 用語

- **仕様書**：プロジェクトについて現在真である事実の集合を書いた文書。
- **節**：仕様書のうち、一つの関心事について単独で読める部分。節ごとに一ファイル。
- **成果物**：仕様書から描かれるもの。コード、テスト、ドキュメント。
- **単位**：成果物を分けた部分。ファイルかディレクトリで、担当する節と境界だけから書き直せる大きさである。振る舞いを持つ単位はそのテストを含む。
- **要素**：単位のうち、外から観測できる振る舞い、公開するシグネチャと引数、内部の構造。
- **構造表**：単位ごとに責務と担当する節を一行ずつ書いた表。
- **担当する節**：構造表でその単位の行に書かれた節。
- **責務**：担当する節にある事実のうち、その単位が実現する範囲。
- **境界**：単位が公開するシグネチャと、単位が依存する他の単位。担当する節から定まる。
- **種**：ユーザーが書く、変更の依頼、機能の案、不具合の報告。数行の文章か一枚のマークダウンで、形式は問わない。
- **依頼**：ユーザーがスキルを起動する指示。
- **影響単位**：一つの変更で書き直すか削除する単位。変わった事実を責務に含む単位、構造表で追加、分割、結合、削除された単位、種が不具合を指す単位、依頼で指定された単位。
- **新版**：一つの変更で書き手が書いた単位。
- **旧版**：その変更の前に統合先のブランチにあった同じ単位。分割か結合で生じた単位では、元になった単位。
- **差し戻し**：検査役の照合結果を書き手に渡し、担当する節から書き直させること。
- **残滓**：仕様書か成果物のうち、旧版、変更の物語、文書の外の会話のいずれかを前提にしなければ存在の理由が無い部分。
- **変更の物語**：一つの変更について、何をなぜ変えるか。
- **ユーザー**：種を書き、仕様書の差分を了承する人。
- **統合先のブランチ**：手順の開始時にチェックアウトされているブランチ。
- **オーケストレーター**：スキルを実行するエージェント。変更の物語を持つ唯一の役。
- **書き手**：一つの単位を、担当する節と境界だけから新規に書く役。redraw.md で定める。
- **検査役**：新しいコンテキストで対象を読むだけの役。何も書かない。
- **規範**：節が満たす条件。spec.md で定める。
- **ブロッカー**：検査の指摘のうち、直さなければ書き手が誤った成果物か食い違う成果物に至るもの。

## 検査と停止

仕様書の検査と単位の検査は、検査役が指摘を挙げ、オーケストレーターが指摘ごとに裁定する形で行います。
検査役は指摘を次の三種に分けて報告し、オーケストレーターは裁定で分け方を改められます。

- **ブロッカー**：どこが何に反するかを特定して書く。
- **後回し**：直せば良くなるが、この変更の目的に要らない指摘。
- **対応不要**：検査役の誤読か好み。

検査は、ブロッカーが無くなれば通ります。
一つの変更の中で、同じ対象への検査は三回までです。
四回目の検査が必要になれば、手順を止め、その時点の指摘と状態をユーザーに報告します。
止めたときは、仕様書の差分と worktree をそのまま残します。

初回の検査役は対象の全文を受け取ります。
再検査の検査役は、前回の指摘と直した後の対象を受け取り、前回のブロッカーの解消と、新たなブロッカーだけを報告します。

後回しの指摘と退けた指摘は、スキルの終わりに理由とともにユーザーに列挙します。
後回しのうちユーザーが採るものは次の種になります。

## 構造表

| 単位 | 責務 | 節 |
|---|---|---|
| `README.md` | index.md の全体と「不変条件」を人に説明する | index.md, common.md |
| `.claude-plugin/plugin.json` | 「配布と書き方」の配布情報 | common.md |
| `skills/spec/` | 「用語」「検査と停止」と spec.md の全体を、オーケストレーターと検査役への指示として書く | common.md, spec.md |
| `skills/redraw/` | 「用語」「検査と停止」と redraw.md の全体を、三役への指示として書く | common.md, redraw.md |

「配布と書き方」の書き方は、全単位の責務に含まれます。

## 配布と書き方

software-engineering は Claude Code のプラグインとして配布されます。
プラグイン名は `software-engineering`、ライセンスは MIT、作者は rinse、リポジトリは https://github.com/rinse/skills です。
`plugin.json` の `version` はリリース時に付けるセマンティックバージョンで、仕様書の対象外です。
スキルは `spec` と `redraw` の二つで、`software-engineering:spec`、`software-engineering:redraw` として提供されます。

成果物は次に従います。

- 文章は日本語で書く。技術文書の文章規範は technical-writing-ja スキルのものに従う。
- スキルは Agent Skills 仕様の `SKILL.md` で、frontmatter に `name`、`description`、`license`、`metadata` を持つ。`metadata` は `author` に作者、`source` にリポジトリの URL を持つ。
- `name` と `description` の合計は 100 トークン以内である。
- スキルが補助文書を持つ場合、`references/` に置き、`SKILL.md` から相対パスで参照する。
