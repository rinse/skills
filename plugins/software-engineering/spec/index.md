# software-engineering 仕様書

## 目的

AI エージェントが、変更を何度重ねても仕様と構造を把握し続けられる開発を実現する。

## 概要

AI エージェントは差分の出力が苦手で、変更を頼まれると旧状態の否定や変更の経緯を成果物に残す。
変更を重ねるほど成果物に履歴が積もり、仕様と構造が読み取れなくなって次の変更の質が落ちる。
このプラグインは、変更を仕様書の更新と、更新された仕様書からの成果物の再描画として行わせる。
一つの変更は、種から仕様書を起こすスキル `spec` と、仕様書から成果物を描くスキル `redraw` の二段で進む。
ユーザーが書くのは種だけで、了承するのは仕様書の差分である。

## 節

- [spec.md](spec.md)：種から仕様書を起こす。
- [redraw.md](redraw.md)：仕様書から成果物を描く。

## 不変条件

- **仕様書が唯一の事実集合である。** 変更はまず仕様書に入り、成果物は仕様書だけから描かれる。
- **仕様書と成果物は歴史的経緯を含まない。** 履歴を書くこと自体が目的の文書（CHANGELOG、ADR、移行ガイド）は除く。
- **仕様書と成果物は事実の水準で一対一である。** 仕様書の事実はいずれかの単位が実現し、単位のどの部分もいずれかの事実で正当化される。

## 用語

- **仕様書**：プロジェクトについて現在真である事実の集合を書いた文書。
- **節**：仕様書のうち、一つの関心事について単独で読める部分。節ごとに一ファイル。
- **成果物**：仕様書から描かれるコード、テスト、ドキュメント。
- **単位**：成果物を分けたファイルかディレクトリで、担当する節だけから書き直せる大きさのもの。振る舞いを持つ単位はそのテストを含む。
- **構造表**：単位ごとに責務と担当する節を一行ずつ書いた表。
- **責務**：担当する節の事実のうち、その単位が実現する範囲。
- **種**：ユーザーが書く、変更の依頼、機能の案、不具合の報告。形式は問わない。
- **影響単位**：一つの変更で書き直すか削除する単位。責務の事実が変わった単位、構造表で追加か削除された単位、種が不具合を指す単位、依頼で指定された単位。
- **変更の物語**：一つの変更について、何をなぜ変えるか。
- **オーケストレーター**：スキルを実行するエージェント。変更の物語を持つ唯一の役。
- **書き手**：一つの単位を担当する節だけから新規に書く役。
- **検査役**：新しいコンテキストで対象を読むだけの役。何も書かない。

## 検査

検査役は指摘を、直さなければ誤った成果物か食い違う成果物に至る**ブロッカー**と、それ以外の**後回し**に分けて報告し、オーケストレーターが指摘ごとに裁定する。
ブロッカーが無くなれば検査は通る。
同じ対象への検査は一つの変更で三回までで、超えれば手順を止め、仕様書の差分と worktree を残したまま指摘と状態をユーザーに報告する。
後回しと退けた指摘は、スキルの終わりに理由とともにユーザーに列挙する。

## 構造表

| 単位 | 責務 | 節 |
|---|---|---|
| `README.md` | 目的、概要、不変条件を人に説明する | index.md |
| `.claude-plugin/plugin.json` | 配布情報 | index.md |
| `skills/spec/` | 用語と検査と spec.md 全体を、オーケストレーターと検査役への指示として書く | index.md, spec.md |
| `skills/redraw/` | 用語と検査と redraw.md 全体を、三役への指示として書く | index.md, redraw.md |

節の一覧と構造表は仕様書の自己記述で、担当する単位を要しない。
「書き方」は全単位の責務に含まれる。

## 配布

Claude Code のプラグイン `software-engineering` として配布する。
ライセンスは MIT、作者は rinse、リポジトリは https://github.com/rinse/skills である。
`plugin.json` の `version` はリリース時に付けるセマンティックバージョンで、仕様書の対象外である。

## 書き方

成果物は次に従う。

- 文章は日本語で書き、technical-writing-ja スキルの規範に従う。
- スキルは Agent Skills 仕様の `SKILL.md` で、frontmatter に `name`、`description`、`license`、`metadata`（`author` と `source`）を持ち、`name` と `description` は合計 100 トークン以内である。
- 補助文書は `references/` に置き、`SKILL.md` から相対パスで参照する。
