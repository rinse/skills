# 仕様書から成果物を描く

スキル `redraw` が担う。
了承された仕様書の差分を成果物に反映する依頼で起動し、統合先のブランチ（起動時にチェックアウトされているブランチ）に変更が一つのコミットとして入った状態で終わる。
push と Pull Request の作成はしない。

## 用語

- **境界**：単位が公開するシグネチャと、依存する他の単位。担当する節から定まる。
- **新版**：一つの変更で書き手が書いた単位。
- **旧版**：その変更の前に統合先のブランチにあった同じ単位。分割か結合で生じた単位では元になった単位。
- **残滓**：旧版、変更の物語、会話のいずれかを前提にしなければ存在の理由が無い部分。
- **差し戻し**：検査の照合結果を書き手に渡し、担当する節から書き直させること。

## 三役

**オーケストレーター**は仕様書、書き手への指示、コミットメッセージだけを書く。
コード、テスト、ドキュメントは書かないが、単位の削除と統合時の衝突の解消は行う。

**書き手**はテストの書き手と実装の書き手に分かれる。
テストの書き手は担当する節からテストを書き、実装の書き手はそのテストを受け入れ条件として受け取り、テストを変更しない。
書き手は担当する節と語の定義、責務、境界、単位の worktree を受け取り、差し戻しでは照合結果も受け取る。
変更の物語と会話は受け取らない。
worktree 内の全てを読んでよいが、旧版は worktree に無い。
境界と他の単位のコードが食い違えば境界に従い、テストと節が食い違えば節に従う。
責務に無いものは書かず、仕様が曖昧で判断した点、仕様に無いが必要と考えた点、境界と他の単位のコードの食い違い、テストが節に無いことを要求している点を報告する。
成果を worktree のブランチにコミットする。
書き手への指示と差し戻しの照合結果は到達状態で書き、「X を Y に変える」という形は無い。

**単位の検査役**は、書き手と同じ節、責務、境界に加えて新版と、あれば旧版を受け取る。
旧版を見てよいのはこの役だけである。

## 手順

1. 統合先のブランチに対する `spec/` の差分と依頼から影響単位を求め、境界の依存順に並べる。
2. 単位ごとにブランチと worktree をプロジェクトルート直下の `.wt/<単位>` に作り、旧版を取り除く。Claude Code の許可はプロジェクト配下にだけ及ぶ。
3. テストの書き手、実装の書き手の順に出す。振る舞いを持たない単位はテストの書き手を省く。依存の無い単位どうしは同時に出す。
4. 単位を検査し、裁定する。差し戻した単位は書き直しののち再び検査する。仕様書に関わる裁定は、その内容を種として `spec` に通し、了承を得てから影響単位を差し戻す。
5. 依存順に統合し、統合のたびに全体のテストが通る状態を保つ。構造表から消えた単位を削除し、worktree とブランチを片付ける。統合先のブランチには一つの変更につき一つのコミットが残り、そのメッセージに変更の物語を書く。書き手の中間コミットは残らない。

## 単位の検査

実装の書き手が単位を書き上げるたびに行い、テストも新版の一部として照合する。

- **過不足**：責務の事実で新版が実現していないものが不足、新版の振る舞い、シグネチャ、内部の構造で責務のどの事実にも正当化されないものが過剰である。
- **隠れた事実の候補**：旧版があれば、旧版にあって担当する節に無い振る舞いを挙げる。落としてよいかは判断しない。
- **残滓**：新版だけを読み、コメントアウトされた旧コード、互換のための二重経路、旧概念を指す名前、変更に由来するテスト名、経緯を述べるコメントを挙げる。

不足、過剰、残滓はブロッカーである。

| 対象 | 裁定 |
|---|---|
| 不足、残滓 | 差し戻す |
| 過剰、仕様に無いが必要と考えた点、テストが節に無いことを要求している点 | 事実として仕様書に加えるか、差し戻す |
| 隠れた事実の候補 | 事実として仕様書に加えるか、事実でないと確認して退ける |
| 仕様が曖昧で判断した点 | 仕様書を一意にし、書き手の判断と違えば差し戻す |
| 境界と他の単位のコードの食い違い | 境界か構造表を直し、影響する単位を差し戻す |
