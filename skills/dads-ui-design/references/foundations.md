# 基本デザインの詳細

デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/ のコンテンツを加工して作成。
基本デザインの一覧は https://design.digital.go.jp/dads/foundations/ 。トークンの実値は [tokens.md](tokens.md) を参照。

## カラー

出典：https://design.digital.go.jp/dads/foundations/color/

### キーカラー

同じ色相の階調から選ぶ。

- **プライマリー**：サイトのトーン＆マナーを決める色。ロゴ、ヘッダー、グローバルナビゲーション、CTA ボタン、アクティブ状態に使う。主要な背景色に対して 4.5:1 以上。プライマリーを複数設定する場合は、それぞれの色相と明度でセカンダリー以下を展開する。
- **セカンダリー**：プライマリーと同じ色相で明度が高いか低い色。副次的な動線や状態表示に使う。背景に隣接する要素なら 3:1 以上、テキストなら 4.5:1 以上。
- **ターシャリー**：セカンダリーと反対の明度に設定する。コントラスト要件はセカンダリーと同じ。
- **バックグラウンド**：白と黒以外の背景色。テキストや要素の色は白か黒の背景を想定して決めているので、この背景に置くときはコントラストを調整し直す。

初期のキーカラーは Blue。例示されているキーカラーは Blue、Green、Neutral、Light Blue、Cyan、Orange、Purple。

### 共通カラー

白から黒のグレー階調（ニュートラルカラー）を基に、テキスト、境界線、背景、UI の構成パーツに使う。テキストは背景と 4.5:1 以上、枠線やディバイダーなどの非テキストは隣接色と 3:1 以上。導入先でニュートラル以外の色味を足してもよい。

### 機能カラー

- **リンクカラー**：慣習どおり未訪問を青、訪問済みを紫（マゼンタ）にし、4.5:1 以上を確保する。紫に青が多いと色覚多様性の観点で見分けにくいため、少し赤みを足して青との明度差を作る。
- **フォーカスカラー**：Yellow-300 と黒の二重構造。いかなる場合も変更しない。
- **検索ハイライトカラー**：シアンかマゼンタから選ぶ。
- **ステートカラー**：ボタンなどはキーカラーを反映して default、hover、active を決める。表現の方式はサイト内で統一する。

### アクセントカラー

特定の要素に注意を引くため、多用しない範囲で使う。装飾以外の用途に使う場合はテキスト 4.5:1、非テキスト 3:1 を確保する。

### セマンティックカラー

意味が割り当てられた色。色相と意味の対応は変えない（エラーを緑にはできない）が、コントラストを確保できる範囲で明度と彩度は調整できる。

- **サクセス**（緑）：成功、安全、完了。
- **エラー**（赤）：失敗、エラー、危険情報、制約条件の提示などの注意喚起。
- **警告**（黄、橙）：警告、禁止事項。

### アクセシビリティ

- DADS はサイズの大きなテキストの緩和（24px 以上、または 18px 以上の太字なら 3:1）を使わず、大きさに関わらずテキストと文字画像に 4.5:1 以上を確保する。
- 非テキスト（UI コンポーネント、グラフィカルオブジェクト、フォーカスインジケーター）は隣接色と 3:1 以上。
- コントラスト要件の対象外：disabled の UI、非選択時のプレースホルダー、純粋な装飾、写真内の読む必要のない文字、ロゴやブランド名。
- グラフやチャートは、要件を満たさない色の近くに 4.5:1 以上のテキストを置くか、伝えたい情報を十分に含む説明テキストを代替として用意する。
- ブランドカラーが 4.5:1 に届かない場合は、同じ色相で明度を調整してキーカラーにする。または、ブランドカラーはロゴと装飾だけに使い、キーカラーは相性のよい別の色を要件の範囲で選ぶ。サイト内のすべての色をブランドカラーの色相で揃える必要はない。
- テキストの色を指定したら、そのテキストが置かれうる要素の背景色も必ず指定する（WCAG 失敗例 F24）。ユーザーがブラウザの背景色を変えている場合に要件を満たせなくなるため。
- 色だけで情報を区別しない（1.4.1）。キーカラーなどのパレットはカラーユニバーサルデザイン推奨配色セットを参考に選ぶ。

## タイポグラフィ

出典：https://design.digital.go.jp/dads/foundations/typography/

- **書体**：サンセリフの Noto Sans JP と、等幅の Noto Sans Mono（いずれも SIL Open Font License 1.1）。OS のシステムフォントの使用は制限しない。ユーザーエージェントが表示フォントを変える前提で、情報伝達を書体に依存させない。
- **太さ**：N（400）と B（700）の 2 段階。
- **大きさ**：48〜64px は視覚的なインパクトが必要な要素。16〜45px は見出しと本文で、本文と UI は 16px 以上が基準。14px はフッターや領域の制約があるときだけ使い、14px 未満は原則として使わない。
- **行高**：読み物の本文は 1.5 倍以上を推奨。CSS では `%` ではなく単位なしの数値で書く。

| 行高 | 主な用途 |
| --- | --- |
| 1.0 | ボタンなど、上下の余白を持たない 1 行のテキスト |
| 1.2 | 管理画面や業務システムで、表示情報量を最優先する |
| 1.3 | 管理画面や業務システムで、表示情報量を優先する |
| 1.4 | 見出しなど、やや大きな文字 |
| 1.5 | 一般的なサイトの本文と見出し（本文の最低限度） |
| 1.6 | 一般的なサイトの本文 |
| 1.7 / 1.75 | 心理的負荷の軽減を考慮した本文。グリッド幅や文字サイズに応じて使い分ける |

### テキストスタイル

名前は「種類-大きさと太さ-行高」。各スタイルに N（400）と B（700）がある。

| 種類 | 用途 | スタイル（大きさ-行高） | 字間 |
| --- | --- | --- | --- |
| Display（Dsp） | ページ冒頭のヘッドコピーなど、強いインパクトが必要なテキスト | 64-140, 57-140, 48-140 | 0 |
| Standard（Std） | 見出しと本文。最も多く使う | 45-140, 36-140, 32-150, 28-150, 26-150, 24-150, 22-150, 20-150, 18-160, 17-170, 16-170, 16-175 | 45 は 0、36〜28 は 0.01em、26 以下は 0.02em |
| Dense（Dns） | 管理画面やデータテーブルなど、表示情報量を優先する | 17-130, 17-120, 16-130, 16-120, 14-130, 14-120 | 0 |
| Oneline（Oln） | 1 行展開を前提とした UI 要素 | 17-100, 16-100, 14-100 | 0.02em |
| Mono | コード | 17-150, 16-150, 14-150 | 0 |

例：本文は `Std-16N-170`、ボタンのラベルは `Oln-16B-100`、データテーブルのセルは `Dns-16N-130`。

### その他の書式

- 日本語フォントはイタリック体を持たず、斜体の合成になって読みにくい。理由がない限り使わない。
- リンクの下線、`<ins>` の下線、`<del>` `<s>` の打ち消し線など、HTML 要素の既定のテキスト装飾は変更・取り消ししない。装飾の線種、色、太さを多く混在させない。

### アクセシビリティ

- 文字サイズを 200% 以上に拡大したり、UD フォントなどに置き換えたりしても、読みやすさと機能が変わらないようにする（レスポンシブデザインで対応する）。
- フォントを変えさせない目的で文字画像を使わない。ロゴタイプは除く。
- 段落間は行高の 1.5 倍以上（文字サイズの 2.25 倍以上）を空ける。
- テキストブロックの幅は全角 40 文字（半角 80 文字）程度を目安にする。ただし、リキッドレイアウト、冒頭の概要、目次、見出しや箇条書きによる構造化など、読みやすさの工夫が複数あればこの目安に縛られない。緊急時バナーのように網羅性を優先するコンテンツも対象外。

## アイコン

出典：https://design.digital.go.jp/dads/foundations/icon/

- 配置位置で 4 種類を定義する。ブロックレベルボックスの先頭がフロントアイコン、末尾がエンドアイコン。行ボックスの先頭がリードアイコン、末尾がテールアイコン。
- アイコンは必ずテキストのラベルと組み合わせる。組み合わせたアイコンには代替テキストを付けない（`<img alt="">`、CSS で配置したアイコンには何も指定せず、`aria-label` も付けない）。
- ラベルがリンクなら、アイコンもリンクの範囲に含める。アイコンとラベルを別々の `<a>` にしない。
- 既存システムの制約などでアイコン単体にせざるを得ない場合は、本来のラベルを代替テキストにし、操作を伴うなら 44×44px 以上のターゲットサイズを確保する。
- アイコンの色は背景に対して 4.5:1 以上。非テキストとしてしか使わないことが保証されている場合に限り 3:1 以上でよい。

## レイアウト

出典：https://design.digital.go.jp/dads/foundations/layout/

- **グリッドシステム**：マージン、カラム、ガターで構成する。基本形は 1 カラム、12 カラム、左メニュー + 12 カラム。
  - カラム幅は本文の文字サイズの整数倍。
  - ガターは本文の文字サイズの 2 倍を原則とする（狭いと隣のカラムの文と誤読しやすい）。
  - 業務システムなどでは左サイドにメニュー領域（固定幅または可変幅）を取り、その右端からマージンを設定する。
- **ブレークポイント**：DADS の作例は 1 つ（768px 未満がモバイルとタブレット、768px 以上がデスクトップ）。導入先で増やしてよい。
- カラム割りは 1〜4 カラムから目的に応じて選ぶ。読み物はカラムオフセットで本文に焦点を当てられる。

### アクセシビリティ

- リキッドレイアウトにする。カラムとガターの一方を可変幅、もう一方を固定幅にする。横スクロールが生じる場合もスクロールバーを隠さない。
- CSS Grid の `order` やグリッド配置は視覚的な並べ替えだけに使う。読み上げ順序とフォーカス順序は DOM の順序のままなので、大きく位置を変えるなら DOM の順序自体を変える。

## リンクテキスト

出典：https://design.digital.go.jp/dads/foundations/link-text/

- 通常のテキストと異なる色に加えて、下線などの色以外の手段で区別する。外部リンクや新しいタブで開くリンクの末尾アイコンには下線を引かないが、クリッカブルエリアには含める。
- リンクの色は容易に区別でき、コントラスト要件を満たし、サイト内で一貫させる。青以外も禁止されないが、その場合はコントラスト、色覚多様性、リンクだと迷わず分かることに配慮する。
- 訪問済み（visited）は未訪問と明瞭に区別できる色にする。hover で文字の太さや大きさを変えると周囲がずれるため、影響がない場合だけにする。
- PDF やダウンロードファイルへのリンクには、ファイル形式や容量を明記する。
- 内部リンクと外部リンクの境界はドメインだけでなくサイトのポリシーで決まる（別ドメインの SaaS 問合せフォームを内部リンクとして扱ってよい）。

### アクセシビリティ

- リンクテキストだけでリンク先を判断できるようにする。リンク先のタイトルや `<h1>` そのもの、ページ内で一意な文字列、目的が分かる長さ、前後の文から分かる、のいずれかを満たす。
- 「ここ」「こちら」だけをリンクにしない。「資料のダウンロードフォームはこちら」なら「資料のダウンロードフォーム」か文全体をリンクにする。一覧の「詳しく見る」が並ぶ場合は記事タイトルをリンクにし、どうしても無理なら `aria-label` で区別する。
- ターゲットサイズは隣接するターゲットと重ならずに 24×24px 以上を目安にする。リンク自体の高さが 16px でも、上下に 4px ずつ余白があれば満たす。

## 余白

出典：https://design.digital.go.jp/dads/foundations/spacing/

- 同種の要素には同じ間隔値を使い、間隔値に規則性（モジュラースケールや比率）を持たせる。
- 基準単位は 8px が一般的で、その倍率から 3〜5 段階の余白スケールを定める。作例は 8px（1 倍）、24px（3 倍）、64px（8 倍）の 3 段階。
- 関連の強い要素の間は狭く、弱い要素の間は広くする（画像とキャプションの間は本文との間より狭く）。重要な要素ほど周囲に大きな余白を与え、見出しの余白は階層が下がるほど小さくする。
- 余白は通常コンポーネントやテンプレートに含まれ、単体で配置しない。トークン化は必要に応じて行う。

### アクセシビリティ

- 空白文字（全角スペースや `&nbsp;`）や両端揃え（`text-align: justify`）で文字の位置やレイアウトを調整しない。単語が分断されてスクリーンリーダーの読み上げに支障が出たり、字間が広がって拡大表示のユーザーが言葉として読めなくなったりする。表のセルや定義リストの見出しでの両端揃えも同様。

## 角の形状

出典：https://design.digital.go.jp/dads/foundations/corner-shapes/

- 5 段階のスタイルを目安とし、スタイルガイドでコンポーネント単位に角丸の値を規定する。
- 同じ角丸でも図形が小さいほど丸く、大きいほど角張って見える。視覚的な印象を揃えるため、コンポーネントの種類と大きさごとに値を調整する。
- 角の形状を変えると特定の図形を強調できる。特定の角だけを丸めてもよい。

## エレベーション

出典：https://design.digital.go.jp/dads/foundations/elevation/

- 既定は高さレベル 0（エレベーションなし）。表現はドロップシャドウ（Style 1〜8）とオーバーレイシェード（モーダル表示時の透過背景）。
- サービス全体で使うコンポーネントを網羅したうえで、必要な高さレベルとその高低差を設計する。余白が十分な UI では高低差を広く、管理画面など過密な UI では狭くして表現を最小限にする。過度に定義しない。
- 厚みのあるコンポーネントの表面はレベル 1。hover で浮くコンポーネントは置かれた高さより 1 レベル以上上を確保する。
- オーバーレイ表示するダイアログなどは、下にある最も高い要素より 2 レベル以上上にする（レベル 1 のボタンがあればレベル 3 以上）。
- オーバーレイシェードは既存の最も高い要素の上に敷き、その面で高さレベルを 0 にリセットする。シェード自体はクリック可能領域ではないので、オーバーレイ側にモードを解除する手段を用意する。モードレスダイアログでは使わない。

### アクセシビリティ

- ドロップシャドウではコントラスト比を確保できない。浮いた要素は置かれた面に対して 3:1 以上のボーダーを持たせる。
- オーバーレイシェードの上の要素にも、コントラストに関わらず必ずボーダーを付ける（透明でもよい）。強制カラーモードではシェードが無効になり、境界が消えるため。
- ダークモードのスタイル例は DADS に含まれない。ダークモードでは影で高さを表現できないので、オーバーレイの高さや視線遮断の表現を最初から策定する。
