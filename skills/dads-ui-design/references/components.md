# コンポーネント一覧

デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/ のコンテンツを加工して作成。
各コンポーネントの公式ページは `https://design.digital.go.jp/dads/components/<slug>/`。寸法、状態、キーボード操作、作例はそちらで確認する。

## 使い分けの早見表

| 目的 | 使う | 使わない |
| --- | --- | --- |
| セクション全体を折りたたむ（同種のセクションが連続する） | アコーディオン | 単一セクション、重要な内容 |
| セクション内の補足情報や詳細オプションを折りたたむ | ディスクロージャー | 展開しないと文意が通らない内容 |
| 同じ主題を観点（概要、仕様など）で切り替える | タブ | サイト内の移動、フィルタリング、手続きの進行 |
| サイト内のカテゴリや目的地へ移動する | 水平メニュー、メガメニュー、メニューリスト | タブ |
| 項目を列挙する | 箇条書きリスト | 見出しと段落の組み合わせ |
| 名前と値、用語と説明のペアを並べる | 説明リスト | テーブル、見出しと段落 |
| 複数の情報や操作を持つアイテムを並べる | リソースリスト（レイアウトによってはカード） | 箇条書きリスト |
| データを比較、分析する | テーブル | カード、リソースリスト |

| 1 つを選ぶ（選択肢 6 個以上） | セレクトボックス | |
| 多くの選択肢から絞り込んで選ぶ | コンボボックス（選択支援タイプ） | |
| 複数を選ぶ | チェックボックス | ラジオボタン |
| 切り替えた結果がその場で分かる設定 | スイッチ | 確定操作が必要な設定 |

| 生命や財産に関わる緊急の通知 | 緊急時バナー | モーダルダイアログ |
| 重要な情報の常設、操作結果の通知 | ノティフィケーションバナー | モーダルダイアログ |
| 入力そのものの条件や制約 | インプットテキストのサポートテキスト | 注釈ブロック、プレースホルダー |
| 手続きに役立つ補足や具体例 | 注釈ブロック | モーダルダイアログ |

## フォームに共通する規範

DADS がこれらを明記しているのはインプットテキスト（ラベルはセレクトボックスなど各フォームコントロール、`disabled` の回避はボタンにも記載）。他のフォームコントロールへの適用はこのスキルによる拡張で、個別の規定があればそちらを優先する。

- ラベルは入力項目を端的に表す。項目が 1 つで画面タイトルなどから意味が明らかなら省略できる。
- 要否ラベルは「※必須」「※任意」のように全角の「※」から書き始める。
- 入力条件や例はサポートテキストに書く。プレースホルダーは使わない（コントラストが低く、入力を始めると消え、スクリーンリーダーで読まれないことがある）。
- エラーテキストは冒頭に全角の「＊」を付け、具体的なエラー内容と訂正方法を書く。静的なテキストとして表示し、`aria-live` や `role="alert"` で読み上げを割り込ませない。
- 無効フィールド（`disabled`）は使わない。編集できない項目は原則として地の文で表示し、`readonly` は既存システムの制約などに限る。
- `maxlength` で最大長を制限しない（末尾の切り捨てやかな入力の途中で切れる問題）。最大長はサポートテキストで示し、超過はサーバーサイドで検証してエラーに超過文字数を示す。
- 入力できる文字種を限定しない。限定する場合は送信時か確認画面で自動変換し、結果をユーザーが確認できるようにする。
- コピーとペーストを禁止しない。メールアドレスを `@` の前後で分割しない。
- 値の変更だけで新しいウィンドウを開く、フォームを送信する、フォーカスを移すといった予測できない変化を起こさない。ボタンやリンクの押下をきっかけにする。
- 穴埋め文章の形にせず、項目ごとにラベルとフィールドを並べる。
- 自由記述は負荷が高い。質問を分割して記述量を減らせないか先に検討する。

## コンテンツの構造

### 見出し `heading`

ページやセクションの主題を表す。

- ページ冒頭に `<title>` に相当する主題をレベル 1 で置き、セクションの前にレベル 2〜6 を置く。
- 見出しレベルを飛ばさない。動的に挿入するコンポーネントの見出しレベルもセクション構造に合わせる。
- 項目の列挙は箇条書きリスト、用語と説明の繰り返しは説明リストを使う。逆に、セクションの主題は箇条書きの階層や説明リストのタイトルで代用せず見出しにする。
- 物語や発話録など、原文に見出しが無い文書に無理に見出しを挿入しない。

### 箇条書きリスト `list`

1 つ以上の項目を列挙する。

- 順不同ならリストマークタイプ、項番自体が情報（条文、規約、手順）なら項番タイプにして項番をテキストで書く。
- `<ol>` とCSS カウンターは使わず `<ul>` で実装する。`<ol>` の項番はコピーできず、項目の追加や並べ替えで番号が変わるため。
- 箇条書きを「・」などのテキストで表現しない。入れ子は正しくマークアップする。
- 複数の情報や操作を含む項目はリソースリスト、名前と説明のペアは説明リスト。

### 説明リスト `description-list`

「説明したいこと」と「その説明文」のペアを繰り返す。用語集、FAQ、仕様の項目と内容、プロフィール、申請内容の確認画面など。

- 比較や行と列の構造化が必要ならテーブル、ペアでない列挙は箇条書きリスト、複数の情報や操作を含む項目はリソースリスト。

### リソースリスト `resource-list`

共通した構成のオブジェクト（見出し、説明、リンク、サブメニューなど）を一覧表示する。各アイテムへの個別アクション（ダウンロード、削除）や、択一選択、複数選択にも使う。

- 比較や分析はテーブル、単純な列挙は箇条書きリスト、名前と説明のペアだけなら説明リスト。
- アイテム全体をクリッカブルエリアにした場合は、中にリンクやボタンを置かない。

### テーブル／データテーブル `table`

データや情報を行と列で構造化した表組。比較や大量データの一覧（データテーブルでは選択、編集、並べ替え）に使う。

- 単なる名前と値のペアは説明リスト。レイアウト目的で使わない。
- シンプルな構造で作る。見出し行を差し込んでグループ化するより表を分割して見出しを付け、入れ子の情報は複数の表に分け、1 レコードは 1 行で表す。スクリーンリーダーは表を線形に読むため、セルと見出しの相互参照が多い表は理解しにくい。

### テーブルコントロール `table-control`

データテーブルの周りに置き、キーワードによる絞り込み、表示件数の変更、関連する操作をまとめる。

- 行の選択や列の並べ替えなどテーブル内で完結する操作はテーブルの機能を使う。複数条件の詳細検索は検索ボックス。

### カード `card`

単一の主題に関するコンテンツをまとめるコンテナ。メディアとテキストのグループ化や、記事や商品などの一覧表示に使う。

- 詳細なデータ比較はテーブル。

### 画像 `image`

`<img>` に対応し、写真、イラスト、図版を埋め込む。画像キャプションや、画像自体のリンクにも対応する。

- 重要な情報は本文のテキストでも提供する。文字画像を使わない（ロゴタイプは除く）。

### イメージスライダー `image-slider`

ギャラリーのように複数のイメージを切り替えて見る。カルーセルの「コンテナタイプ - マルチ - 幅狭サイズ」で実装する。

### 引用ブロック `blockquote`

段落単位の引用。文献や資料の一部、法令や規定の条文に使う。

- 本文の見栄え、コラム的な文脈の切り替え、強調のために使わない。

### 注釈ブロック `notice-block`

強調された補足情報。手続きや入力に必要な補足、具体例の提示に使う。

- 入力や操作そのものの条件はサポートテキストに書く。
- 読まなくても進められる補足は、中にディスクロージャーを入れて折りたためる。
- 本文の調子を変える装飾として使わない。

### ディバイダー `divider`

セクションやコンテンツのグループ間の視覚的な区切り。全幅タイプ（セクションやリストの区切り、インタラクティブな領域とそうでない領域の区別）とインセットタイプ（同じセクション内のグループ化）がある。

- 余白はリストで 8px 以上、セクションで 16px 以上取る。ディバイダーは余白の補助であり、それが無いと文意が伝わらない構成にしない。

### 目次 `toc`

長いページの見出しを取り出し、冒頭に目次として置く。箇条書きリストと組み合わせて階層化できる。

- 「このページの目次」という見出しを削除しない。
- 見出しの文言をそのまま使う。階層が深い場合は含める階層を絞る。

### チップラベル `chip-label`

状態や分類を示すキーワード。申請一覧のステータス（受付中、審査中、完了）や、お知らせの種別、記事のタグに使う。

- 色だけで意味を伝えず、必ずテキストで示す。色の種類を増やしすぎない。アクセントカラーを使うならコントラストを確保する。
- ユーザーが選択、入力した値にはチップタグを使う。

### チップタグ `chip-tag`

ユーザーが選んだ、入力した値をアイテムにして表示し、個別に削除できるようにする。検索の絞り込み条件、メールの宛先など。

- 状態や分類にはチップラベルを使う。削除を元に戻せない場合は使わず、チェックボックスを検討する。

## 折りたたみと切り替え

### アコーディオン `accordion`

同種のセクションが連続するとき、それらを折りたたんで一覧性を上げる。よくある質問、更新履歴、申請者の属性ごとの説明など。

- 表示領域を小さくするためだけに使わない。ヘッダーで概要が示され、ボディが追加や補足の情報である場合に限る。
- 重要な情報を折りたたまない。独立した単一のセクションには使わない。
- セクション内の一部を折りたたむならディスクロージャー。
- ヘッダーは概要文にする。リターンリンクはヘッダーへのページ内リンクにし、ラベルをヘッダーと揃える。
- `<details>` 要素で実装する。

### ディスクロージャー `disclosure`

メイン情報に対する補足や注釈、メイン機能に対する詳細オプションを折りたたむ。フォームの例外説明、グラフの元データの表、動画の文字起こし、詳細検索など。

- 表示領域を小さくするためだけに使わない。展開しなくても地の文だけで必要最低限の情報が伝わるようにする。
- セクション全体を折りたたむならアコーディオン。
- タイトルは簡潔で説明的にし、アクションを示唆せず、開閉状態に関わらず一定にする。
- `<details>` 要素で実装する。

### タブ `tab`

同じ主題のコンテンツを、概要、仕様、レビューなどの観点ごとに切り替える。

- 複数のセクションを同時に開いて比較したいならアコーディオン。サイト内の移動は水平メニュー。手続きの進行はステップナビゲーション。条件による絞り込みにはフォームコントロールを使う。

### カルーセル `carousel`

複数のスライドを順番に見る。使用に注意が必要なコンポーネント。

- 使えるのは 2 つの場合だけ。サイトを象徴するグラフィックをファーストビューに置く打ち出しタイプ（`<title>` 自体がカルーセルの見出しとして機能する場合に限る）と、「新着情報」など見出しを伴うトピックのコンテナタイプ。
- きちんと読んでほしい情報を入れない。自動再生させない（DADS のカルーセルは自動再生の仕組みを持たない）。複数の異なるトピックを同居させない。
- カードや見出しとリストなど、カルーセル以外の表現を先に検討する。使う場合は本コンポーネントを使い、スライドの数とテキストを少なくする。

## フォームとアクション

### ボタン `button`

アクションの実行やページ遷移のきっかけ。

- 重要度に応じて、塗り（プライマリー）、アウトライン（セカンダリー）、テキスト（ターシャリー）を使い分ける。プライマリーは 1 画面に原則 1 つ。セカンダリーは文脈ごとに原則 3 つまで（4 つ以上ならフローを見直す）。ターシャリーはキャンセルなどの中断に使い、原則 1 つ。
- 重要度を色の違いだけで区別しない。
- デスクトップでは進める操作（OK、完了、次へ）を右寄せ、進めない操作（キャンセル、戻る）を左寄せにし、右ほど重要度を高くする。モバイルの縦積みでも同じ意味的な順序にする。配置ルールはサイト内で統一する。
- 無効化（`disabled`）は避ける。押せない理由が分からないため、送信時にエラーで案内する。どうしても無効化するなら、すぐ近くに有効になる条件を書く。`disabled` はタブフォーカスが当たらないので、必要なら `aria-disabled` の注意点を公式ページで確認する。
- ターゲット領域は 44px 以上。Small と X-Small は上下の余白で確保する。
- アイコンだけのボタンには代替テキストを必ず付ける。ページ遷移をもたらすボタンは hover でカーソルを pointer にする。
- フォーカス順序を変える目的で `tabindex` を使わない。表示順序と DOM の順序を揃える。

### インプットテキスト `input-text`

名前や電話番号など、1 行のテキストを入力する。規範は上の「フォームに共通する規範」を参照。

### テキストエリア `textarea`

自由記述のテキストを入力する。

- 「その他を選んだ方だけ記入」のように、質問を分割したうえで使う。
- 文字数制限があればラベルに最大文字数を書く。最大がおおむね 20 文字を超える、またはスクロールが要る長さなら、文字数カウンターを表示する。

### セレクトボックス `select`

複数の選択肢を提供する。

- 選択肢が 5 個以下ならラジオボタンを使う。長すぎるリストは事前の質問で減らせないか検討する。

### コンボボックス `combobox`

`<select>` を拡張した選択支援タイプ（用意された選択肢を文字列で絞り込む）と、`<input type="text">` を拡張した入力支援タイプ（自由入力に候補を提示する）がある。

- 絞り込みが不要ならセレクトボックス、候補の提示が不要ならインプットテキスト。

### チェックボックス `checkbox`

複数の選択肢から複数を選ぶ。

- 1 つしか選べないならラジオボタン。チェックボックスはテキストの左に置く。

### ラジオボタン `radio`

選択肢から 1 つだけを選ぶ。

- 選択を解除できないので、任意項目では「あてはまるものはない」などの選択肢を設ける。

### スイッチ `switch`

切り替えると即座に反映され、その場で結果が分かる設定に使う。オンとオフ、または両方にラベルを付けた 2 択（摂氏と華氏など）。

- その場で結果が分からない設定や、保存などの確定操作が要る設定には、チェックボックスかラジオボタンを使う。

### 日付ピッカー／カレンダー `date-picker`

年、月、日の 3 つのテキスト入力フィールドと、必要に応じたカレンダーで日付を入力する。

- `<select>` と `<input type="date">` は避ける（生年月日などで長いスクロールが必要になる）。直接入力だけにするか、カレンダーを併用するかを文脈で決める。
- 生年月日などでは `autocomplete`（`bday-year` など）を指定する。

### ファイルアップロード／ドロップエリア `file-upload`

`<input type="file">` に対応し、1 つまたは複数のファイルを選択してアップロードする。

- ドロップエリアだけにせず、必ずファイル選択ボタンを置く（ドラッグできない人のため）。

### 検索ボックス `search-box`

サイト内検索。検索範囲の絞り込みメニューや、よく検索されるキーワードへのショートカットを持てる。

- データテーブルの絞り込みにはテーブルコントロールも検討する。

## ナビゲーション

### ヘッダーコンテナ `header-container`

ロゴ、ヘッダーコンテナアイテム（ユーティリティリンク、ランゲージセレクター、検索ボックスなど）、水平メニュー、ハンバーガーメニューボタンを内包するヘッダー。ワイド（フル、スリム）、ミディアム、コンパクトの構成がある。

### 水平メニュー `horizontal-menu`

主要なナビゲーションを横に並べ、サイト内のカテゴリや目的地へ誘導する。サブメニューも持てる。縦に並べるならメニューリスト。

- 項目が多すぎたら整理、階層化する。モバイルではハンバーガーメニューボタンとモバイルメニューで表示する。
- ラベルは遷移先のページ名にし、「詳細」「その他」を避ける。同じ主題の切り替えはタブ。

### メガメニュー `mega-menu`

デスクトップで、水平メニューから第二階層以下を一覧表示する大きなドロップダウン。リンクに説明文や画像を添えられる。モバイルではハンバーガーメニューボタンとモバイルメニュー。

- ホバーでは開かず、水平メニューの項目を選択したときに開く。
- 第三階層のリンクをすべて並べられない場合は使わない（表示されたものが全部だと受け取られるため）。

### メニューリスト `menu-list`

メニューアイテムを束ねる。ローカルメニューとして置くほか、メニューリストボックスやメガメニューの中に入れる。カテゴリタイトルやディバイダーでセクションを明確にし、CTA の挙動を明確に示す。

### メニューリストボックス `menu-list-box`

テキストラベルと開閉アイコンのオープナーで開閉し、中にメニューリストを入れる。起点の左端か右端に揃えて表示し、クリックで開く。

### モバイルメニュー `mobile-menu`

タップ操作を考慮したメニュー。ハンバーガーメニューボタン、ドロワーと組み合わせる。スタンダードタイプとアコーディオンタイプがある。

### ハンバーガーメニューボタン `hamburger-menu-button`

主にモバイルで、モバイルメニューを開くボタン。ヘッダーの左端か右端に置く。

- 原則としてアイコンとテキストラベルを組み合わせたものを使う。領域が足りない場合に限り、ページの言語に合わせた「メニュー」か「MENU」を含む条件付きの形を使う。

### ドロワー `drawer`

画面の四辺から展開するコンテナで、モバイルメニューなどを入れる。必ずモーダルで、親要素はオーバーレイシェードで覆われる。「閉じる」ボタンで閉じる。

### パンくずナビゲーション `breadcrumb`

サイト階層内の現在位置を示す。ヘッダーとページ見出しの間に置く。

- デスクトップでは長ければ改行する。モバイルでは改行（ページ上部か下部に置く）か、改行しない横スクロールを使う。

### ユーティリティリンク `utility-link`

コンパクトな横並びのリンクリスト。ヘッダーやフッターに置き、「お問合わせ」「よくあるご質問」「ヘルプ」など頻繁に使うリンクや、法的に必要なリンクを並べる。

### ランゲージセレクター `language-selector`

表示言語を選ぶ。デスクトップでは上隅に、ハンバーガーメニューのあるレイアウトではメニュー内に置く。

- セレクター自体の表記は表示言語に関わらず英語の「Language」にし、言語のリストはそれぞれの言語で書く。

### ページナビゲーション `page-navigation`

分割された一覧やテーブル、順番に並んだコンテンツを前後に移動する。「13 ページ（全 24 ページ）」のように現在位置も示せる。

- 手続き全体の現在位置はステップナビゲーション。
- 前後のページが無い場合はボタンを無効化せず、非表示にする。

### ステップナビゲーション `step-navigation`

一連の手続きを論理的なステップで示し、全体の流れ、現在位置、完了やスキップやエラーの状態を把握できるようにする。

- 一時的な処理の待機はプログレスインジケーター、ページの前後移動はページナビゲーション。

### ボトムナビゲーション `bottom-navigation`（非推奨）

使わない。画面下部の固定はモバイルブラウザの UI やジェスチャーと競合し、DOM の最下部に置くとキーボードやスクリーンリーダーで到達しにくい。代わりにページ上部の水平メニュー、モバイルではハンバーガーメニューボタンとモバイルメニューを使う。

### スクロールトップボタン `scroll-top-button`（非推奨）

使わない。固定配置のボタンが拡大表示時にコンテンツを隠し、DOM の最下部に置くとキーボードで到達できない。ページ先頭への移動はブラウザの標準機能（Home キーなど）で足りる。

## 通知とフィードバック

### 緊急時バナー `emergency-banner`

本来のコミュニケーションを中断してでもファーストビューを占有して注意を促す。ページ上部に置く。

- 生命や財産に影響する緊急性の高い情報だけに使う。それ以外や長期間の掲示はノティフィケーションバナー（掲示し続けるとアラート疲れで効果が薄れる）。
- デスクリプションは全角 100 文字程度までにし、詳細は別ページに用意する。

### ノティフィケーションバナー `notification-banner`

サイト全体、またはページや要素単位の重要度の高い情報を、ユーザーの操作に関わらずサイト側から提示する。

- タイプはサクセス、エラー、警告（セマンティックカラー）と、それ以外の重要情報の情報提示（Info）。デザインスタイルはスタンダードとカラーチップから選ぶ。
- アイコンとタイトルが必須。デスクリプション、年月日、閉じるボタン、アクションボタンは任意で、リンクやアクションの有無で共存できない要素がある。
- ページ上部、関連するコンテンツの近く、画面内に固定して追従、のいずれかに配置する。

### モーダルダイアログ `modal-dialog`

表示中はダイアログ内しか操作できない。削除などの破壊的な操作の確認や、ダイアログ内で完結する短いメッセージに使う。

- ユーザーのボタン押下なしに表示しない。
- 処理の完了やステータスの変化、告知情報、ナビゲーションメニューには使わない（それぞれ結果の表示、緊急時バナーかノティフィケーションバナー、ドロワーなど）。
- 補足情報はサポートテキスト、注釈ブロック、ディスクロージャーを先に検討する。
- アクションボタンがあるなら閉じるボタンを付けない。
- ダイアログ外の情報を読まないと判断できない内容や、フォームを入れない。
- 確認ダイアログだけを安全対策にしない。誤って削除しない設計や、取り消し、復元を検討する。

### プログレスインジケーター `progress-indicator`

ユーザーの操作に対して処理中であることを伝える。画面全体の読み込み待ちはサークルタイプかリニアタイプ、画面の一部の処理中はアニメーションしない砂時計タイプ。

- サークルとリニアを画面の一部に使わない。スケルトン UI は使わない。手続き全体の進行はステップナビゲーション。
