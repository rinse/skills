# DADS に沿った UI 設計

デジタル庁デザインシステム（DADS）に沿って、画面・コンポーネント・スタイルを設計する。
情報の意味に合うコンポーネントを選ぶことと、外観を導入先に合わせて変えてもアクセシビリティの骨格を崩さないことが、このスキルの核。

## 哲学

- **アクセシビリティファースト**：「誰一人取り残されない、人に優しいデジタル化を。」の実現のため、アクセシビリティを最優先事項に置く。基準は WCAG 2.2、JIS X 8341-3:2016（WCAG 2.0 と同一内容）、WAI-ARIA。
- **プラットフォーム型**：特定の組織のブランドを持たない。導入先のブランドでトークンを再定義した**ローカルデザインシステム**（スタイルガイド）を作ってから使う。初期値はデジタル庁ウェブサイト由来の編集の起点であり、外観を規定するものではない。
- **準拠規約ではなく枠組み**：デザインを機械的に生成するルールではない。コンポーネントはプリミティブな情報要素の組み合わせで、足りない場合は枠組みの中で独自の定義を追加する。

## 編集できる範囲と守る要件

ローカルデザインシステムで変えてよいものと、変えた後も満たす要件。

| 基本デザイン | 編集できる | 編集後も守る |
| --- | --- | --- |
| カラー | キーカラー（ブランドカラーで上書き可）、共通カラーへの色味の追加、セマンティックカラーの明度と彩度 | テキストと背景 4.5:1 以上（大きな文字の 3:1 緩和は使わない）、非テキストと背景 3:1 以上、セマンティックカラーの色相と意味の対応 |
| タイポグラフィ | 書体の大きさと行高の追加・変更 | 本文と UI は 16px が基準、14px 未満は原則使わない、読み物の本文の行高は 1.5 倍以上 |
| 余白 | 基準単位と倍率スケール | 間隔値の規則性、インタラクティブ要素のターゲットサイズ |
| 角の形状 | コンポーネント単位の角丸 | なし |
| エレベーション | 高さレベルの種類と高低差 | 浮いた要素は置かれた面に対し 3:1 以上を影ではなくボーダーで確保 |
| リンクテキスト | リンクの色（青以外も可） | 色以外の装飾（下線など）との併用、リンクだと認識できること |
| レイアウト | カラム割り、ブレークポイントの数 | リキッドレイアウト、視覚上の配置と読み上げ順序の一致 |

どの導入先でも変えないもの：

- フォーカスインジケーター（Yellow-300 と黒の二重構造）。
- アイコンは必ずテキストのラベルと組み合わせる。
- コードスニペットに含まれる WAI-ARIA の指定と強制カラーモード対応。書き換えても取り除かない。

## 基本の値

- **フォント**：Noto Sans JP と Noto Sans Mono。太さは 400（N）と 700（B）の 2 段階。
- **テキストスタイル**：`Std-16N-170` のように「種類-大きさと太さ-行高」で表す。種類は Dsp（ヘッドコピー）、Std（見出しと本文）、Dns（業務画面などの高密度表示）、Oln（1 行の UI）、Mono（コード）。
- **カラー**：初期のキーカラーは Blue。セマンティックカラーは成功が緑、エラーが赤、警告が黄または橙。リンクは未訪問 Blue-1000、訪問済み Magenta-900。白背景のテキストには Gray-536（#767676）以上の濃さのグレーを使う。
- **余白**：8px を基準単位とし、その倍率（例：8 / 24 / 64px）から 3〜5 段階を選ぶ。
- **レイアウト**：12 カラム。ブレークポイントは 768px の 1 つ（モバイルとデスクトップ）。ガターは本文の文字サイズの 2 倍。
- **ターゲットサイズ**：ボタンとアイコン単体の操作要素は 44×44px 以上。インラインのリンクは 24×24px 以上。

## ローカルデザインシステムを決める

UI を設計する前に、導入先のローカルデザインシステムを決める。手順の詳細は [references/local-design-system.md](references/local-design-system.md)。

1. 既存のものを探す。まず記録ファイル `docs/design-system.md` を見る。あればそれに従い、以下は省く。
2. 無ければ、見つかったもの（スタイルガイド、`--color-key-*` の上書き、ブランド資産など）を示して、ユーザーに次から選んでもらう。
   1. **既存のものを使う**：リポジトリ内のもの、またはユーザーが示す Figma や文書。
   2. **固まっている部分だけ指定する**：キーカラーなど決まっている値だけを受け取り、残りを DADS の様式に沿って導出する。
   3. **すべて任せる**：DADS の初期値（キーカラー Blue など）をそのまま使う。
3. 結果を `docs/design-system.md` に記録する。既存のものに「守る要件」への違反があれば、直さずにユーザーへ報告する。

キーカラーを変えたら `scripts/contrast.py --key` で 13 段階すべてを検証する。

## 進め方

1. 画面の情報を、意味に合うコンポーネントに割り当てる。「領域を小さくしたい」「目立たせたい」といった見た目の都合で選ばない。迷ったら [references/components.md](references/components.md) の使い分けを確認する。
2. ローカルデザインシステムの値を当てる。定義が無い項目は DADS の初期値を使う。
3. 上の「守る要件」と、使った各コンポーネントの注意点に照らして確認する。

references/ に無い細部（寸法、状態、キーボード操作など）は、各コンポーネントの公式ページを読んで確認する。推測で補わない。

## references/ と scripts/ の索引

references/ の内容は、2026-10-13 版のドキュメントとデザインデータ（Figma）v2.18.0 時点のもの。

- [references/local-design-system.md](references/local-design-system.md)：ローカルデザインシステムの探し方、3 つの選択肢それぞれの進め方、キーカラーからの導出、記録ファイルのテンプレート、DADS の Figma での作成手順。ローカルデザインシステムを決めるときに開く。
- [references/foundations.md](references/foundations.md)：基本デザイン 8 種の詳細。キーカラーの役割、テキストスタイルの全一覧、余白、レイアウト、エレベーション、アイコン、リンクの規範とアクセシビリティ要件。値の根拠や細則が必要なときに開く。
- [references/tokens.md](references/tokens.md)：CSS カスタムプロパティの実値と、フォーカスインジケーター・リンク・ボタンの CSS。実装するときに開く。
- [references/components.md](references/components.md)：全コンポーネントの用途、使う場面と避ける場面、代替、主な規範、公式ページの URL。コンポーネントを選ぶとき、レビューするときに開く。
- [references/resources.md](references/resources.md)：Figma データ、コードスニペット、npm パッケージ、アクセシビリティ基準などの外部リソースとライセンス、出典表記。成果物を公開するときや外部資料を探すときに開く。
- `scripts/contrast.py`：2 色のコントラスト比（`contrast.py FG BG`）と、キーカラー 13 段階の一括検証（`contrast.py --key C50 ... C1200`）。色を決めたとき、変えたときに実行する。
