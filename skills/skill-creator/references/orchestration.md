# Subagent に作業を委譲するスキルの取り決め

オーケストレーターが Subagent に作業を委譲するスキルで、展開のときにスキル固有の判断の候補に加える事柄。

## 委譲するのは範囲の閉じた作業に限る

- 委譲するのは、担当範囲だけを見れば進められ、他の作業とのずれを後のレビューで正せる作業のうち、オーケストレーターのコンテキストを圧迫するもの。
- 一貫性の維持と最終判断（進める、差し戻す、止める）は、オーケストレーターが自分で行う。Subagent に事実の抽出を任せるときは、判断までさせない。

## 渡すのは所在、受け取るのは結論

- Subagent には、資料の本文ではなく所在（パス、URL など）を渡し、自分で読ませる。
- 返してほしい内容と形式を指示し、結論だけを受け取る。

## Subagent は質問できない前提で指示する

- Subagent は実行中にユーザーへ質問できない。判断がつかないときは推測で進めず、止まった箇所、理由、人間に決めてほしいことを返させる。
- Subagent に許す作用（外部への作用、書き込める場所）を指示に書く。

## モデルは作業の難易度で選ぶ

- 判断の余地が少ない作業ほど弱いモデルに任せる。弱いモデルほど、変更の対象、倣うべき既存のもの、完了条件まで指示を具体的にする。
- 強いモデルに上げる前に、弱いモデルと、より具体的な指示で足りないかを検討する。

## 並列の作業は書き込む場所を分ける

- 複数の Subagent を並列に動かすときは、同じファイルや同じ状態を書き換える作業を同時に並べない。
